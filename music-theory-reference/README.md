# music-theory-reference

A modular, open-source reference for music theory fundamentals, organized so the **abstract theory** is kept cleanly separate from **instrument implementations** — starting with guitar, with room for piano, bass, violin, brass, and beyond.

## Philosophy

This repository is built around one core design goal: **decouple theory from instruments.**

- **Abstract theory** lives in:
  - `01-foundations/`
  - `02-harmony-and-analysis/`

  These modules are **instrument-agnostic**. They explain pitch, intervals, scales, chords, rhythm, harmony, voice leading, and analysis without referring to frets, keys, valves, bows, or any particular sound-producing mechanism.

- **Instrument mappings** live in:
  - `03-instrument-mappings/`

  These modules implement the same theory on specific instruments. The first implementation is **guitar**, but the structure is designed so new instruments can be added without changing the core theory.

This separation means:
- The same interval, scale, or chord formula is defined once, in abstract form.
- Each instrument shows how that formula is realized on its own physical system.
- New instruments can be added by following a mapping template instead of refactoring the foundation.

## Module Guide

### 01 Foundations

- **01-pitch-and-frequencies.md** — pitch classes, octaves, 12-TET, frequency ratios, scientific pitch notation, cents, harmonics.
- **02-intervals.md** — interval quantity and quality, semitones, frequency ratios, inversion, consonance/dissonance, tritone, shorthand notation.
- **03-scale-formulas.md** — major, natural/harmonic/melodic minor, all seven diatonic modes, pentatonic and blues scales.
- **04-chord-construction.md** — triads, seventh chords, extensions, alterations, inversions, chord quality.
- **05-rhythm-and-meter.md** — pulse, tempo, note values, rests, time signatures, simple/compound/complex meters, syncopation, tuplets, polyrhythm.

### 02 Harmony and Analysis

- **01-circle-of-fifths.md** — key signatures, relative major/minor, closely related keys, modulation, chord relationships.
- **02-diatonic-harmony.md** — diatonic triads and seventh chords, primary triads, functional roles, cadences.
- **03-voice-leading.md** — smooth voice motion, common tones, leading-tone resolution, guide tones, inversions, styles.
- **04-roman-numeral-analysis.md** — scale-degree labeling, chord quality, inversions, minor keys, secondary dominants, borrowed chords.

### 03 Instrument Mappings: Guitar

- **01-fretboard-layout-and-standard-tuning.md** — fretboard as a coordinate system, EADGBE tuning, the G→B major-third shift, fret math, scientific pitch on the neck.
- **02-caged-system-and-movable-shapes.md** — C, A, G, E, D shapes as movable fretboard regions, root locations, shape-to-key mapping.
- **03-scale-box-patterns-and-3nps.md** — 5-box position system vs. 3-notes-per-string scale layout, strengths and trade-offs.
- **04-alternate-tunings.md** — Drop D, DADGAD, Open G, string-offset thinking, drone/modal character, capo vs. alternate tuning.
- **05-triads-and-drop-chords.md** — triad string groups, inversions, Drop 2 and Drop 3 voicing logic, voice-leading across the fretboard.

### 04 Data

Machine-readable JSON files for programmatic use:

- **intervals.json** — interval name, semitone count, shorthand code, approximate just-intonation and 12-TET frequency ratios, cents.
- **scale-formulas.json** — scale names, degree formulas, semitone offset arrays, step patterns, parent-scale and mode-index relationships.
- **chord-formulas.json** — chord quality, formula arrays, semitone stacks, diatonic context, extension/alteration notes.
- **guitar-fretboard-map.json** — full coordinate map for strings 1–6 across frets 0–24: MIDI note, scientific pitch notation, frequency in Hz. Generated by `scripts/generate_fretboard_data.py`.

### Scripts

- **generate_fretboard_data.py** — builds `guitar-fretboard-map.json` from a tuning specification. Supports custom tunings via CLI arguments.

## Using the JSON Data

The files in `04-data/` are intended to be consumed directly by apps, tooling, or analysis scripts. They are plain JSON, so they work with any language.

### Example: loading a scale formula

```python
import json

with open("music-theory-reference/04-data/scale-formulas.json") as f:
    data = json.load(f)

for scale in data["scales"]:
    print(f"{scale['name']} → {scale['formula']}")
    print("  semitones:", scale["semitones"])
```

### Example: looking up an interval by short code

```javascript
import fs from "fs";

const intervals = JSON.parse(
  fs.readFileSync("music-theory-reference/04-data/intervals.json", "utf8")
).intervals;

function byShortCode(code) {
  return intervals.find((i) => i.shortCode === code);
}

console.log(byShortCode("m3"));
// → minor third: semitones 3, ratio in 12-TET ~1.1892
```

### Example: building a fretboard coordinate lookup

```python
import json

with open("music-theory-reference/04-data/guitar-fretboard-map.json") as f:
    board = json.load(f)

# coordinateIndex is keyed as "string,fret"
note = board["coordinateIndex"]["2,3"]
print(note["scientificPitch"], note["midi"])
```

Because the guitar map is generated from a Python script, you can also regenerate it with a different tuning instead of hand-editing the JSON:

```bash
python music-theory-reference/scripts/generate_fretboard_data.py
python music-theory-reference/scripts/generate_fretboard_data.py --output custom.json \
  -- E2 A2 D3 G3 B3 E4
```

## Adding a New Instrument

See `templates/instrument-mapping-template.md` for the recommended workflow.

In short:
1. Create `03-instrument-mappings/<instrument>/`.
2. Start with the instrument's pitch-production system and coordinate model.
3. Map the existing abstract theory onto that system without changing `01-foundations/` or `02-harmony-and-analysis/`.
4. Add any instrument-specific data files to `04-data/` with clear naming and schema.
5. If there is a generator script, place it in `scripts/` and document its output.

The point is to keep theory shared and instruments modular.

## Conventions

- Markdown uses standard notation and inline LaTeX for formulas such as $1 - \flat 3 - 5 - \flat 7$.
- Guitar diagrams are text-based in ASCII/tab form so they are scannable without special rendering.
- Core theory modules do not mention instruments explicitly.
- Instrument modules assume the core theory and explain the physical mapping on top of it.
